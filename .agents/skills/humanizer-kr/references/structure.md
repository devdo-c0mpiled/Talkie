# 구조 패턴 (패턴 18-25)

## 과학적 근거

KatFishNet 연구 (Park et al., ACL 2025):
- AI 텍스트의 문장 길이 표준편차가 평균의 15% 미만 (인간은 30-50%)
- AI 텍스트의 POS n-gram 다양성이 인간보다 낮음 (AUC 82.99%)

XDAC 연구 (Ko et al., KAIST, ACL 2025):
- AI는 서식문자(ㅋ, ㅠ, !, ?) 사용률 1% (인간 26%)
- AI는 반복자음(ㅋㅋㅋ, ㅠㅠ) 사용률 12% (인간 52%)
- AI는 표준 이모지 선호, 인간은 한국어 자음 반복과 특수문자 사용
- AI 한국어에서 "것 같다", "에 대해" 같은 정형화된 완곡 표현이 빈번

Burstiness 연구 (GPTZero):
- AI 텍스트 burstiness 점수: 0.18-0.30 (균일)
- 인간 텍스트 burstiness 점수: 0.65-0.85 (다양)
- Burstiness = 문장 길이의 표준편차 / 문장 길이의 평균


## 패턴 18: 문장 리듬 단조

### 진단 방법

텍스트의 문장 길이(어절 수)를 나열했을 때 변동이 적으면 AI 가능성이 높다.

**AI 패턴:** 12, 11, 13, 12, 11, 14 (거의 균일)
**인간 패턴:** 3, 18, 7, 2, 22, 5 (불규칙)

### 해결 방법

- 짧은 문장(1-5어절)과 긴 문장(15-25어절)을 의도적으로 섞기
- 한 단어 문장도 괜찮다: "된다." "아니다." "맞다."
- 의문문, 감탄문 섞기
- 문단 길이도 다양하게

### 추가 예시

**Before:**
> 첫째로 속도가 빠릅니다. 둘째로 안정성이 높습니다. 셋째로 확장이 용이합니다. 넷째로 문서화가 잘 되어 있습니다.

**After:**
> 빠르다. 안정적이고 확장도 쉽다. 문서화가 잘 되어 있다는 점도 생각보다 큰 장점인데, 오픈소스 프레임워크에서 문서가 좋은 건 흔한 일이 아니다.


## 패턴 19: 3의 법칙 남용

### 한국어에서의 발현

- "A하고, B하며, C합니다" (연결어미 3연속)
- "A, B, 그리고 C를 통해" (나열+접속)
- "혁신, 협업, 성장" (명사 3개 나열)
- "속도, 안정성, 확장성" (특성 3개 강조)

### 해결 방법

- 2개로 줄이거나 4개 이상으로 늘리기
- 나열 대신 서술형으로 풀기
- 하나씩 별도 문장으로 설명

### 추가 예시

**Before:**
> 이 서비스는 편리하고, 경제적이며, 효율적입니다. 고객은 신뢰하고, 만족하며, 재방문합니다.

**After:**
> 이 서비스는 편리하고 경제적이다. 고객 만족도가 높아서 재방문율도 좋다.


## 패턴 20: 접속사 과다

### 감시 대상 빈도 순

1. 또한 (가장 빈번)
2. 그러나 / 하지만
3. 따라서
4. 게다가
5. 한편
6. 더불어 / 아울러
7. 더 나아가
8. 이에 따라
9. 결과적으로
10. 반면(에)

### 접속사 대체 전략

| 접속사 | 대체 방법 |
|--------|----------|
| 또한 | 생략하고 바로 연결 |
| 그러나 | -지만, -는데 연결어미 사용 |
| 따라서 | -므로, -니까, -어서 연결어미 사용 |
| 게다가 | 생략 또는 -기까지 하다 |
| 한편 | 문장 분리 |

### 판단 기준

연속 3문장 이상이 접속사로 시작하면 문제다.


## 패턴 21: 경어체 균일성

### 한국어 종결어미 스펙트럼

**격식체 (합쇼체):** -습니다, -ㅂ니다, -습니까
**비격식 높임 (해요체):** -아요/-어요, -죠, -거든요, -네요, -더라고요, -잖아요, -는데요
**격식 낮춤 (해라체):** -다, -이다, -했다
**비격식 낮춤 (해체):** -해, -야, -지, -거든

### 문체별 자연스러운 혼용

**블로그:**
> 이건 꽤 괜찮아요. 써보니까 빠르더라고요. 한 가지 아쉬운 점이 있긴 한데요. 설정이 좀 복잡하거든요. 그래도 한번 해놓으면 편하죠.

**기술문서:**
> 이 API는 RESTful 방식을 따릅니다. 인증은 JWT를 사용하는데요. 토큰 만료 시간은 기본 1시간이에요.

**학술:** -습니다 균일성이 적절할 수 있음 (이 패턴 적용 제외)


## 패턴 22: 볼드 핵심어: 설명 리스트

### 발현 형태

```markdown
- **속도:** 처리 속도가 향상되었습니다
- **안정성:** 99.9% 가동률을 보장합니다
- **보안:** 엔드투엔드 암호화를 지원합니다
```

### 해결 방법

서술형 산문으로 전환:
> 처리 속도가 향상되었고 가동률은 99.9%다. 엔드투엔드 암호화도 지원한다.

또는 단순 나열이 필요하면 볼드 없이:
> - 처리 속도 향상
> - 99.9% 가동률
> - 엔드투엔드 암호화


## 패턴 23: 이모지 장식

### 감시 대상

- 제목/소제목 앞의 이모지
- 목록 항목 앞의 이모지
