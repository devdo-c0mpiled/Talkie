# 다이어그램 빌더

Node.js 24가 설치된 저장소에서 실행한다. npm 의존성 설치나 API 키 없이 빌더를 사용할 수 있다.

```sh
npm run diagram:builder
```

출력된 `http://127.0.0.1:4323`을 연다. 종료는 터미널에서 Ctrl+C를 누른다. 포트를 사용 중이면 `DIAGRAM_PORT=4324 npm run diagram:builder`로 실행한다. 로컬 개발 도구이며 앱 배포에는 포함되지 않는다.

## 편집과 공유

1. 기본 설계 예시를 편집하거나 **JSON 불러오기**로 팀의 그래프 파일을 연다.
2. 노드의 ID·이름·종류·상태와 출발·도착 연결을 편집한다. **JSON 편집 → JSON 적용**도 지원한다.
3. 노드 검색과 클릭으로 내용을 확인한다. **모션 재생**은 노드 배열 순서의 시뮬레이션이다. 실제 시스템 호출이나 실행 이벤트를 수집하지 않는다. **상태 복원**은 JSON에 기록된 상태로 돌아간다.
4. **Archify 렌더링**을 누르면 아래에 독립 뷰어가 열린다. 뷰어에서 포커스·확대·이동과 모션 기능을 사용할 수 있다.
5. **JSON 저장**은 재편집할 입력 파일, **HTML 저장**은 팀에 전달할 독립 문서다. **Archify JSON 저장**은 별도 Archify 도구에서 쓸 변환 결과이며 이 빌더의 입력 형식과 다르다.

렌더링 후 편집하면 이전 HTML 저장 버튼이 비활성화된다. 다시 렌더링한 뒤 저장한다. 변경 내용은 자동 저장하지 않으므로 닫기 전에 JSON을 저장한다. 모션 줄이기를 켠 환경에서는 빌더의 CSS 애니메이션이 정지한다. 시뮬레이션의 상태 변경은 계속되며 **모션 정지**로 멈출 수 있다.

## CLI로 HTML 생성

```sh
npm run diagram:build -- tools/diagrams/examples/talkie-proposed.json output/diagrams/talkie.html
npm run diagram:test
```

HTML과 `talkie.html.json`을 생성한다. HTML은 렌더러와 스타일을 포함한다. `output/diagrams/`는 Git에서 제외한다. 공유할 원본 JSON은 `tools/diagrams/examples/` 또는 팀이 정한 문서 경로에 보관한다.

## 입력 형식

```json
{
  "title": "문서 검색 흐름",
  "nodes": [
    {"id": "search", "label": "검색", "kind": "backend", "status": "running"},
    {"id": "store", "label": "문서 저장소", "kind": "database", "status": "pending"}
  ],
  "edges": [{"source": "search", "target": "store", "label": "조회"}]
}
```

DataGround와 insight-rag의 `{ "type": "flow_graph", "title": "...", "data": { "nodes": [], "edges": [] } }` 봉투도 받는다. 외부 봉투의 run ID·version 등은 변환하지 않는다. 이름이 없으면 ID를 사용하고, 종류·상태 기본값은 `backend`·`pending`이다.

- ID: 영문자로 시작, 영문·숫자·밑줄·하이픈, 최대 64자. 중복은 오류다.
- 노드: 1~40개. 이름·종류는 최대 64자, 제목은 최대 160자.
- 연결: 최대 100개. 존재하지 않는 노드와 자기 자신으로의 연결은 오류다. 연결 이름은 최대 64자.
- 상태: `pending`, `running`, `done`, `failed`.
- 종류: `frontend`, `backend`, `database`, `cloud`, `security`, `messagebus`, `external`. 그 외 종류는 원문을 보존하고 Archify 구성요소 유형만 `backend`로 변환한다.

자동 배치는 진입차수 기반 열 배치를 사용한다. 순환에 걸린 노드는 별도 열에 배치해 관계를 보존한다. 복잡한 순환·긴 이름은 연결선이나 라벨이 겹칠 수 있으므로 브라우저에서 검수한다. 빌더의 미리보기와 Archify의 선 배치는 다를 수 있다. 라이브 상태가 HTML에서 자동 갱신되지는 않는다.

## 재사용 모듈

- `tools/diagrams/graph.mjs`: 입력 검증·정규화, 자동 배치, Archify 변환. 브라우저와 Node.js에서 import할 수 있다.
- `tools/diagrams/build.mjs`: `renderGraph(input)`으로 `{ candidate, html }` 반환. 임시 디렉터리에서 별도 Node 프로세스로 렌더링하고 정리한다.
- `tools/diagrams/server.mjs`: 로컬 편집 서버. `127.0.0.1`에 바인딩하고 동일 출처 JSON 요청만 받는다. 입력은 128KB, 렌더링은 한 번에 하나·30초로 제한한다.
- `tools/diagrams/web/`: 노드·연결 폼, 상태 모션, JSON 입출력, sandbox iframe 미리보기.

앱의 실시간 화면에 연결하려면 `normalizeGraph`와 `graphLayout`을 사용하고 실제 실행 이벤트의 node ID와 상태를 연결한다. 현재 빌더는 로컬 문서 제작 범위다. npm 앱 번들·Workers 바인딩·배포 설정은 변경하지 않는다.

## 조사한 구현과 출처

DataGround의 `frontend/src/components/agent/FlowGraphMap.tsx`와 `frontend/src/lib/visualArtifacts.ts`에서 공통 노드 상태, 검색 강조, DAG·순환 배치, 진행 상태 모션을 확인했다. 기준 커밋은 `376f7657d94fc9b9126577cb90cd8cadb2044b3a`다.

insight-rag의 `packages/web_ui/components/artifacts/FlowGraphView.tsx`, `packages/web_ui/lib/types.ts`, `packages/web_ui/app/globals.css`에서 같은 nodes/edges 계약과 상태별 노드 표현을 확인했다. 기준 커밋은 `cf7de8634ccbfb20eafffacce5e95b9ab55d0674`다. 두 레포의 화면은 Archify를 직접 사용하지 않는다. Next.js·i18n·Dagre 의존성을 옮기는 대신 공통 데이터 계약에 맞는 독립 어댑터를 작성했다. DataGround의 글자 스크램블과 뱀 모양 배치는 이번 모듈에 포함하지 않았다.

[Archify](https://github.com/tt-a1i/archify)는 `ba701d20a55ed6f139484d9ead7ff45671fe40eb`의 3.2.0 렌더러를 사용한다. 실행에 필요한 renderers·schemas·locales·assets·brand-marks를 원본 그대로 포함했다. 원본 파일별 SHA-256은 `tools/diagrams/vendor/archify-source.json`에 기록했다. MIT 라이선스와 브랜드 자산의 별도 고지는 vendor 안의 `LICENSE`, `THIRD_PARTY_NOTICES.md`에 보존했다. 예시에서 브랜드 로고는 사용하지 않는다.

## 팀 스킬

`.agents/skills/talkie-diagrams/SKILL.md`를 저장소에 포함했다. 지원하는 에이전트에서는 `$talkie-diagrams`로 호출한다. 자동 탐색을 지원하지 않는 도구에는 다음처럼 요청한다.

> `.agents/skills/talkie-diagrams/SKILL.md`를 읽고, 확인한 소스 구조로 다이어그램 JSON과 HTML을 만들어줘. 설계 예시와 구현된 경로를 구분해줘.

전역 스킬 설치는 필요하지 않다. 이 스킬은 Talkie의 저장소 경로를 사용하므로 다른 레포에 복사할 때는 `tools/diagrams/`와 사용 문서도 함께 옮긴다.
