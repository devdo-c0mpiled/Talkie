# 팀 문서 작성 규칙과 스킬 사용법

팀원이 같은 기준으로 개발 문서와 PR을 작성하도록 문체 스킬을 저장소에 함께 보관한다. 저장소를 받으면 개인 홈 디렉터리에 스킬을 설치하지 않아도 원문을 읽어 적용할 수 있다. 별도 실행 프로그램이나 API 키는 필요하지 않다.

## 적용 범위

개발 문서, PR 제목·본문, 커밋 메시지는 한국어로 작성한다. 코드 식별자, API 이름, 명령어, 경로, 오류 코드와 인용 원문은 바꾸지 않는다. 영어 제목이 있는 외부 문서와 스킬 원문도 그대로 보관한다.

한국어 문체는 `humanizer-kr`, 영어 및 공통 문장 구조는 `humanizer`를 참고한다. 과장, 번역투, 반복과 불필요한 설명을 줄이되 기술적 의미와 근거를 보존한다. 격식 있는 문서를 억지로 구어체로 바꾸거나 확인하지 않은 경험과 감정을 넣지 않는다.

사용자 요청과 프로젝트 규칙이 스킬보다 우선한다. 특히 스킬의 감정 추가, 종결어미 혼용, 중간 교정본 출력 지침은 팀 문서에 일괄 적용하지 않는다. 문체 규칙을 CI에서 기계적으로 강제하지 않고 작성자와 리뷰어가 문맥에 맞게 점검한다.

## 저장소에 포함한 스킬

| 스킬 | 용도 | 원문 |
| --- | --- | --- |
| humanizer-kr | 한국어 문장의 번역투·반복·과장 점검 | [SKILL.md](../.agents/skills/humanizer-kr/SKILL.md) |
| humanizer | 영어와 공통 문장 구조 점검 | [SKILL.md](../.agents/skills/humanizer/SKILL.md) |

두 스킬은 MIT 라이선스다. 각 디렉터리에 원본 `LICENSE`를 포함했고 [sources.json](../.agents/skills/sources.json)에 저장소 주소, 고정 커밋과 파일별 SHA-256을 기록했다. `humanizer-kr`의 참고 문서도 함께 보관한다. 외부 저장소의 플러그인 설정, 워크플로와 실행 스크립트는 포함하지 않는다.

## 팀원 환경에서 사용하기

1. 저장소를 받은 뒤 루트의 [AGENTS.md](../AGENTS.md)를 읽는다.
2. 작업에 두 `SKILL.md`를 적용한다. `.agents/skills`를 인식하는 도구는 저장소 스킬을 사용하고, 인식하지 않는 도구에는 아래 지시문을 전달한다.
3. 최종 문장과 코드 diff를 함께 확인한다. 자동 스킬 인식 여부는 팀원이 사용하는 도구와 버전에 따라 확인해야 한다.

```text
이 저장소의 AGENTS.md와 아래 파일을 읽고 문서 작성에 적용해 주세요.
.agents/skills/humanizer-kr/SKILL.md
.agents/skills/humanizer/SKILL.md
문서와 커밋 메시지는 한국어로 작성하고 기술적 의미와 근거를 보존해 주세요.
```

스킬은 AI 도구가 읽는 작성 지침이다. 파일을 보관하는 것만으로 모든 편집기에서 자동 교정되는 것은 아니다. 개인 환경에 같은 이름의 스킬이 있어도 팀 작업에서는 이 저장소에 고정한 파일을 기준으로 삼는다.

## 문서와 PR 작성

문서는 목적과 현재 동작부터 설명한다. 구현 예정인 기능은 계획으로 표시하고 실행하지 않은 검사를 통과했다고 쓰지 않는다. 검증 결과에는 실행 명령과 결과를 적고, 제한이 있다면 해당 결과 옆에 설명한다.

PR에는 변경 이유, 실제 변경 범위, 검증 결과를 적는다. 변경량이 작으면 짧은 문단과 검사 목록으로 충분하다. 관련 없는 개선 제안이나 작업 중 대화 내역은 넣지 않는다.

커밋 메시지는 변경 내용을 직접 적는다.

```text
팀 문서 작성 규칙과 문체 스킬 공유
통역 평가에서 시간 정정 사례 추가
하네스 종료 시 테스트 세션 정리
```

## 교정하면 안 되는 자료

평가 입력, 기대값, 프롬프트와 실제 발화·전사·번역 결과는 측정 근거다. 문체를 다듬으면서 내용을 바꾸지 않는다. 자료 변경이 필요하면 원본과 변경 이유를 남기고 별도 변경으로 검토한다.

화면 문구는 요청한 범위에서만 수정한다. 빈 공간을 채우려고 설명을 추가하거나 승인된 슬로건을 임의로 바꾸지 않는다. 버튼·필드·상태·오류 문구는 짧고 명확하게 유지한다.

## 스킬 업데이트

1. `sources.json`의 현재 커밋과 업데이트할 원본 커밋 사이의 차이를 확인한다.
2. 라이선스, 새 지침과 참조 파일을 검토한다. 실행 코드나 외부 전송 지침이 추가됐다면 별도로 검토하고 자동 실행하지 않는다.
3. 검토한 커밋에서 필요한 파일을 원본 그대로 가져온다. 기존 저작권 고지와 라이선스를 보존한다.
4. 파일 목록·커밋·SHA-256을 `sources.json`에 반영한다. 삭제된 파일도 목록과 사본에서 정리한다.
5. 변경 내용과 팀 규칙에 미치는 영향을 한국어 PR로 남긴다.

팀 규칙을 바꿀 때는 외부 원본을 수정하지 않고 `AGENTS.md`와 이 문서를 수정한다. 원본 스킬의 내용 변경은 고정 버전을 갱신하는 PR에서 다룬다.
